# Git 環境診斷與恢復

依序分清本機 Git、提交身分、登入客戶端與遠端儲存庫。

1. 查看已開視窗及程序。確認使用者說的 Git 是 CLI、GitHub Desktop 或瀏覽器網頁。
2. 執行 git --version，確認實際 Git 路徑。使用 git -C 指向目標專案。
3. 查看 status、branch 與既有 remote。remote 可能帶憑證，顯示前遮罩 URL 中的認證部分。
4. 作者錯誤時查本專案與有效全域 user.name、user.email，以及設定來源。已有相符的明確使用者設定可沿用。
5. 若仍缺少，可查已開啟桌面工具的 Git 設定與使用者明確指定的本機專案設定。別人的 commit author 或公開 GitHub 帳號名稱不足以決定使用者的 Email。
6. 無法確認姓名／Email 才詢問。繼續完成修改、測試、差異審查與封裝。取得身分後優先設本專案 local config。
7. gh auth status 只檢查 gh。網頁已登入時，已授權的網頁工作可以使用該 session；不匯出 Cookie 或繞過登入。
8. 提交後查 log 與工作區狀態。發布另外確認目標 owner/repo、可見性、授權與已授權範圍，再驗證遠端提交。

## 有界修復

| 發現 | 可繼續工作 | 需補資訊 |
|---|---|---|
| Git 存在，作者缺少 | 修改、驗證、暫存、準備提交內容 | 已確認的姓名與 Email |
| gh 未登入，網頁已登入 | 網頁上的已授權操作 | CLI 推送若必要，需其獨立認證 |
| 遠端未設定 | 本地提交與封裝 | 真實發布目標 |
| 多個同名視窗 | 重新定位 window-id 與產品 | 不靠標題猜測 |
| 安裝清單沒有但程序存在 | 查程序路徑與實際版本 | 不重複安裝 |

不要自行捏造 noreply Email、提交者名稱或全域身分。不要因 GitHub 網頁已開啟就宣稱已能從 CLI 推送。
