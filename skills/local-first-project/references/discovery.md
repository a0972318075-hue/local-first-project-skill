# 本機軟體發現

## Windows

從視窗與程序開始。若桌面工具可用，先列視窗，辨識目標軟體及對話框。程序 Path 可能需要額外權限，失敗記為未知。

依序使用唯讀查詢。
- Get-Command 查 PATH，包含產品的命令別名。
- 查目前使用者及公用開始功能表捷徑，解析目標路徑。
- 查 HKCU、HKLM 與 WOW6432Node 的 Uninstall，以及 App Paths。
- 必要時查 Store 應用與套件管理器清單。
- 查產品官方記載的預設目錄及已知 portable 位置。

不任意執行找到的同名檔案。核對路徑、產品資訊、發布者或可信來源。
不要使用 Win32_Product 作為例行清單，避免觸發 MSI 修復。
不要掃描私人文件內容來找應用程式。

## macOS / Linux

macOS 查已開視窗／程序、Applications 與使用者 Applications、PATH 和現有套件管理器。
Linux 查程序、PATH、desktop entries、現有套件管理器及 Flatpak/Snap。
平台未測試時明示未測試，避免將 Windows 的成功推論到其他系統。

## 記錄格式

產品 | 搜尋來源 | 結果／錯誤 | 路徑 | 版本 | 真實功能測試 | 下一步

只有相關搜尋已完成且未命中，才標記 missing-after-search。部分來源無法存取時保留不確定性。

## 必須先提供本機證據

在說「未安裝」「無法執行」或請使用者補設定前，先建立最小證據表。
使用者說已開啟時，立即重新列視窗與程序，不沿用先前未命中的結論。

| 能力層 | 檢查內容 | 狀態 |
|---|---|---|
| 安裝 | 實際執行檔、版本與可用位置 | 已確認／未知／尚未檢查 |
| 執行 | 目前視窗與程序對應 | 已確認／未知／尚未檢查 |
| 設定 | 任務所需設定與作用範圍 | 已確認／缺少／尚未檢查 |
| 登入 | 每個獨立客戶端的認證狀態 | 已確認／未登入／尚未檢查 |
| 權限 | 目前操作的權限與錯誤 | 可用／被拒／尚未檢查 |
| 功能 | 一次與任務直接相關的測試 | 通過／失敗／尚未檢查 |

不能從視窗標題推定產品。名為 GitHub 的視窗可能是瀏覽器網頁、PWA 或 GitHub Desktop。以程序路徑、畫面及產品資訊辨識。
Git CLI、GitHub Desktop、瀏覽器 GitHub、gh CLI 分別檢查。網頁登入不代表 gh 已登入；提交身分缺少不代表 Git 未安裝。
權限不足無法讀取時保留 unknown，不能記為未安裝。

證據表只保留任務必要資訊。帳號可在本地確認，發布版測試紀錄應去識別；不讀取或輸出 Token、Cookie、密碼及完整 credential store。
